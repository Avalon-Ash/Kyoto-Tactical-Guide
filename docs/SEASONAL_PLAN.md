# 歲時記年度活動計畫（待實作）

2026-11-06。使用者授權本輪研究、移除首頁按鈕及列計畫，**未授權本輪製作年度資料庫**。

## 現況盤點

`public/seasonal.html` 是 2026/6/4–6/17 個人旅程：固定航班、十四日行程、六月活動及每日行事曆。事件只有單一 `date`，多日期寫在 `displayDate`，時刻為自由文字；人潮曲線沒有逐項來源。不能直接視為全年資料，更不能把 2026 日期改年份就當成已確認活動。

本輪只移除首頁入口，保留原頁與內容作歷史存檔。恢復入口前必須完成下列年度資料與查詢驗收。

## 資料與查證

- 活動主檔：穩定 ID、中日名稱、場地、地區、類型、主辦者、官方網址、慣例季節。列出所有已知活動，公開收錄範圍與最後查核日，不宣稱涵蓋全京都所有活動。
- 年度場次：連結主檔，年度、開始／結束日期、實際開放日或排除日期、每日時段、時區 Asia/Tokyo、費用／預約資訊、官方年度來源、查核日。
- 狀態區分「當年度已確認、待公告、延期、取消」。日期未公布的年度活動仍在總表，不能混入確定日期的出遊結果；取消活動明確標示且預設不列為可參加。
- 跨年活動用完整日期，週末限定、休館日、分段場次不能以連續日期取代。舊頁的航班與私人行程不移入公共活動主檔；人潮數字未查證前不沿用。

## 使用流程

先選年度，顯示全部已知活動；可切春（3–5）、夏（6–8）、秋（9–11）、冬（12–2）。冬季明示跨年範圍，例如 2026/12–2027/2，不隱去次年場次。

使用者選取起訖日後，依實際日期、時間排列可參加活動。判斷與區間相交：活動開始 ≤ 選取結束、活動結束 ≥ 選取開始，再套實際開放日與排除日期。結果呈現名稱、地點、可參加日期、狀態、官方連結；日期無效或結束早於開始時提示修正。這階段是活動清單，不自動承諾交通可行的旅遊排程。

## 分期與驗收

1. **S1 盤點與來源**：整理既有活動為候選；由京都官方活動入口、寺社與主辦者公告建立年度清單，逐項留來源與查核日；先確認預計涵蓋區域及維護人力。
2. **S2 資料層**：另設活動 schema／雙語 locale，不改動景點 ID；新增狀態、日期與來源驗證。必要 schema 設計另提具體 diff 審核。
3. **S3 查詢頁**：文庫一致的圖紋／字體，年度列表、季節切換、日期區間及空結果；桌機／手機、雙語、鍵盤與無動態皆驗收後才恢復入口。
4. **S4 年度維護**：每年建立待公告名單；公告後人工核對年度日期、異動與取消。顯示過期查核提示；自動擷取或排程更新另提方案，不在本輪引入大型依賴或發布流程。

資料測試須涵蓋跨年、閏日、同日起訖、活動開始早於查詢區間、區間最後一天、休館日、非連續場次、取消／待公告；篩選不漏掉期間內仍在舉行的活動。
