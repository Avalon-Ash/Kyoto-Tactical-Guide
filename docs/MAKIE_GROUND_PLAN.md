## 0. 觀察依據與限制

- 畫面：本機 dev server 跑 `origin/main` HEAD `b13462a`（就是線上部署的 commit），`/toji-study/index.html` 南區，舊管線與 `?three=1` 各拍 1440px 全景與 2x 特寫。截圖存在 session scratchpad，不提交。
- 截圖是無頭 Chromium＋SwiftShader 的軟體渲染，粒子閃光和實機 GPU 不完全相同。最終驗收以實機畫面為準。
- **線上預設仍是舊管線**，`?three=1` 才是 three.js。兩條管線的地有同樣的問題。本企劃只改 three.js；要讓線上看到，得接著做 T5（three 設為預設）。舊管線不回補，避免同一件事調兩次。
- 本 session 的網路擋住德川美術館與 dig-it 的網域，這次沒辦法重看原作照片。以下對原作的描述都來自 11-05 與 11-14 已記錄的查證；標「待查證」的項目要等照片確認。

## 1. 現在的地 vs 初音的地

| # | 現況（截圖所見） | 初音的地 | 落差 |
|---|---|---|---|
| G1 透漆深度 | 像奶茶色紙板上撒金點：底色偏灰褐、對比低，粒子只是亮度不同的同色點 | 金粉沉在琥珀色透漆裡：深層的粉被漆濾成紅褐，淺層的粉亮金，底是暖深棕。整面看起來像從裡面透出光 | 少了「深度造成的顏色變化」，這是最大的差距 |
| G2 鏡面 | 地面幾乎沒有反光，盒子傾斜時整面亮度不變 | 研磨後的漆面是鏡面：傾斜時會有一道柔和的窗光滑過整面，粉在光帶裡才會閃 | 移光少了主角；`mCoat()` 的環境反射只佔 .045 |
| G3 疏密 | `dens = .60 + .16·noise`，整面幾乎一樣密 | 梨子地有濃淡：霞、土坡、建築周圍是濃梨子地，空曠處較疏；交界用蒔きぼかし（粉由密到疏）過渡 | 少了疏密場；所有濃淡現在只靠光照 |
| G4 霞 | 左上的霞是兩條淡色、硬邊的平塗長條，讀起來像污漬 | すやり霞是乾淨的金帶（濃梨子地或金地），邊緣明確，兩端收圓 | 霞的材質要和地分開，而且要比地更金 |
| G5 土坡、州浜 | 前景沙丘鋪滿大顆、隨機、方向亂的切金，像豹紋或碎石 | 土坡是肉合研出：低隆起，金粉由肩到腳ぼかし；切金是細小方片，沿等高線一排一排排，只放在岩面與土坡肩 | 切金太大、太滿、沒有排列 |
| G6 水 | 一條灰色鋪面加銀線，看起來像柏油路 | 水是在梨子地上直接用銀付描畫波線，底下還透得出梨子地；岸邊線密、中央疏，彎處有渦 | 灰底要拿掉 |
| G7 盒側與蓋縫 | 盒側是一片均勻的暗金褐平面，沒有粒子、沒有紋飾；蓋縫只是一條黑線 | 料紙箱側壁延續山水（11-05 研究：「和歌散布蓋面及側面」「連續山水、側壁、蓋縫與金具」）；使用者 §3.4 也定過「箱側也有紋飾」 | 側面要跟蓋面用同一套梨子地，並延續低對比的霞與土坡 |

## 2. 工作包

順序依「改一處、整面受益」排。D1、D2 是同一個 shader，先做；做完就該看得出差別。

| 包 | 內容 | 主要檔案 | 驗收重點 |
|---|---|---|---|
| D1 透漆梨子地 | 重寫 `mNashiji`：三層粉各自有深度 d，顏色乘上琥珀吸收 `exp(-σ·d)`（σ 對藍最大、對紅最小），深層偏紅褐，淺層亮金。底漆壓暗、轉暖（約 `#2a1608` 一帶），粉的亮度拉開，提高對比。粒徑照 11-14 的照片觀察縮到接近像素，遠看平均成暖金，近看才分得出顆粒（沿用 `mFlake` 的 `vis` 淡入）。`MATERIALS.ground`、`BOX_MATERIALS.side` 的底色一起對齊 | `plate/three-pack.js`（`MAKIE_COMMON_GLSL`、材質表） | 遠看平均色是暖琥珀金，不是灰褐；3 倍特寫分得出細、中、大三種粒，深層的偏紅 |
| D2 漆面鏡光 | 在漆面加一道寬而柔的窗形反射（clearcoat 層，不是金屬層），位置跟盒子傾斜走；移光時光帶掃過，放手後回到靜止位置。光帶裡的粉閃光加強，光帶外壓低。上限要夾住，不能把建築洗白 | 同上，加 `three-renderer.js` 的 uniform | 傾斜時能看到一道光帶滑過整個蓋面；建築與樹不被洗白；夜間仍是暖金 |
| D3 疏密場 | 烘一張密度場：離霞、土坡、建築輪廓越近越密（濃梨子地），空曠處疏，交界平滑（蒔きぼかし）。現有 `uFine0` 的 RGB 已分別用於起伏、覆蓋、線，A 也要先查清楚，所以另烘一張單通道圖，不擠進舊通道 | `plate/bake.js`（新函式）、`three-renderer.js`、`three-pack.js` | 不看建築，光從地就讀得出構圖的重心 |
| D4 霞與土坡 | 霞改成獨立材質：濃梨子地＋金溜，邊緣乾淨、兩端圓，比地明顯更金。土坡用 D3 的密度從肩到腳ぼかし；切金縮成現在的約 1/3，沿等高線成排，只放在土坡肩與岩面 | `three-pack.js`（mat 2、3、4、7 分支）、必要時改各區的 `plate/*.js` 霞形 | 霞不再像污漬；前景不再像豹紋；切金看得出排列方向 |
| D5 水 | 拿掉灰色底，改成梨子地加一點冷色，上面畫銀付描波線：岸邊密、中央疏，彎處加渦。保留現有的流動與 ring | `three-pack.js`（mat 12 分支） | 水下看得到梨子地的粒；整條讀成「水」而不是「路」 |
| D6 盒側與蓋縫 | 盒側不再用平的 MeshPhysicalMaterial 加 flake 法線，改用同一套 D1 梨子地；延續蓋面的霞與土坡，對比壓低到蓋面的一半。蓋縫做成一道細金線。覆輪的材質（金或銀）**待查證** | `three-renderer.js`（box 材質）、`three-pack.js` | 盒側看得到粒子和紋飾；蓋縫是金線而不是黑線 |
| D0 參照（可並行） | 拿到原作照片再對一次：文箱與料紙箱的側面紋飾、覆輪材質、霞的技法、地的濃淡分布。需要使用者在環境網路設定允許 `www.tokugawa-art-museum.jp`、`online.bunka.go.jp`、`dig-it.media`，或直接給照片 | `MAKIE_REFERENCES.md` 補一節 | D6 的「待查證」解除 |

做法：依 HANDOFF §4，美術由主代理直接做，不派外部。D1–D2 是同一個 shader 的連續調整，派出去反而要來回傳截圖。D3 的烘焙函式範圍明確，如果使用者想省主代理的額度，可以單獨派出。

## 3. 驗收

- 每包做完，同一視角拍「前後對照」：南區＋另外兩區（建議北區、右京區，地的面積大），1440px 與 375px，日與夜，靜止與移光中，以及 3 倍特寫。
- 數值輔助（不取代看圖）：從截圖量蓋面空地的平均色相與亮度標準差。D1 後色相要往橙偏、亮度標準差要上升（對比變高）。前後數字記在執行紀錄。
- 效能：每像素最多三層細粉加一層大片，不增加 `mFlake` 的總呼叫數；手機 375px 的幀時間不低於現在的 three 版。
- 程式：`npm run lint`、`npx --no-install tsx validate_data.js`、`npm test`、`npm run build`。只改 shader 數值時，至少跑 test 與 build。
- 最終：使用者在實機上看 `?three=1`。SwiftShader 截圖不算最終證據。

## 4. 風險與回退

- 全部在 `?three=1` 後面，線上預設不受影響；不滿意就 revert 該包的 commit。
- 光帶（D2）最容易過頭：太亮會讓整盒變塑膠。上限先保守，再看實機調。
- 疏密場（D3）多一張貼圖，換函時的烘焙時間會變長；`bakeMs` 要記錄，增量超過 30% 就改成降解析度烘。
- 地變暗以後，平塗佔位的狐、鳳凰、鶯會更突兀。這是 T4 的事，不在本企劃內，但截圖時要註明。
